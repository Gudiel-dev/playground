# Algorithms
## The Playground Roadmap

> "Don't memorize algorithms. Understand why they exist."

---

# Philosophy

The Algorithms section isn't meant to become a list of coding interview questions.

It's a museum of problem solving.

Each project should answer one question:

> **"Why would someone invent this algorithm?"**

Understanding comes before optimization.

Visualization comes before memorization.

---

# Learning Philosophy

I don't want to learn algorithms like this:

Bubble Sort

↓

Read code.

↓

Memorize.

↓

Forget.

Instead:

A problem appears.

↓

Think of a solution.

↓

Build it.

↓

Improve it.

↓

Discover the algorithm.

The goal is to develop the habit of reasoning, not simply remembering names.

# Learning Roadmap

## Level 0 — Thinking Like a Programmer

Before studying algorithms, learn to think through problems.

Projects:

- Find the largest number
- Find the smallest number
- Count words
- Reverse a string
- Palindrome checker
- Caesar cipher
- FizzBuzz

These projects build logical thinking.

---

## Level 1 — Searching

The first real algorithms.

### Linear Search

Imagine looking for your keys.

Pocket.

Backpack.

Desk.

Drawer.

One place at a time.

Until you find them.

That's Linear Search.

---

### Binary Search

Imagine searching inside a dictionary.

You don't start on page one.

You open it in the middle.

Wrong?

Go left.

Wrong?

Middle again.

Repeat.

Each step removes half of the remaining pages.

That's Binary Search.

---

## Level 2 — Sorting

Sorting teaches different ways of organizing information.

### Bubble Sort

Imagine arranging books by height.

Compare two books.

Swap them.

Move one position.

Repeat.

The largest book slowly "floats" toward the end.

Hence the name:

Bubble Sort.

---

Other sorting algorithms:

- Selection Sort
- Insertion Sort
- Merge Sort
- Quick Sort

Each one represents a different strategy.

---

## Level 3 — Recursion

At first...

Recursion feels impossible.

Then suddenly...

Everything clicks.

Projects:

- Countdown
- Factorial
- Fibonacci
- Folder traversal
- Tree traversal
- Fractals

Recursion teaches you how a problem can solve smaller versions of itself.

---

## Level 4 — Data Structures

Algorithms become much more powerful when combined with data structures.

Topics:

- Arrays
- Objects
- Stacks
- Queues
- Linked Lists
- Trees
- Graphs
- Hash Maps

---

## Level 5 — Real-world Algorithms

This is where algorithms stop feeling academic.

Projects based on:

- Autocomplete
- Music playlists
- Google Maps
- Chess
- Pathfinding
- Compression
- Image processing

At this point you're no longer "studying algorithms."

You're building software.

# The Playground Way

I don't want each project to look like this:

Bubble Sort

↓

Code.

↓

Done.

Instead...

Each project should become a tiny interactive museum exhibit.

---

## Bubble Sort

Instead of only showing code...

Display bars.

```
▇ ▂ ▆ ▅ ▃
```

Click **Start**.

Watch the bars move.

```
▂ ▇ ▆ ▅ ▃

↓

▂ ▆ ▇ ▅ ▃

↓

▂ ▆ ▅ ▇ ▃
```

You don't just read Bubble Sort.

You watch it think.

---

## Binary Search

Display a sorted row of numbers.

```
3 7 11 15 19 25 31
```

Searching for **19**.

Highlight the middle.

```
3 7 11 [15] 19 25 31
```

Too small.

Discard the left half.

```
19 25 31
```

Highlight the middle again.

Found.

The algorithm becomes visible.

# Something Worth Remembering

The purpose of this section is not to prove that I know algorithms.

The purpose is to understand how they think.

If someone visits this repository years from now, I want them to be able to say:

> "I finally understand why Bubble Sort works."

# Final Thought

Algorithms are not magic.

They are ideas.

Ideas that thousands of programmers discovered over decades by trying to solve problems a little better than before.

This page isn't about collecting algorithms.

It's about collecting ways of thinking.
